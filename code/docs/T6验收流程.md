# T6 实际使用流程

演示账号密码均为 `Demo-2026`。组织者使用 `su_qing`，另一位组织者使用 `zhao_ming`，管理员使用 `he_qm`，参与者使用 `lin_zy`、`chen_an`。

## 名单与统计

1. 用 `su_qing` 登录，打开“名单与统计”，选择本人活动和场次。核对名单中的姓名、账号、状态、报名及签到时间。
2. 查看报名人数、到场人数、缺席人数、剩余名额。切换场次后，名单和统计应一起变化；无报名的场次显示空名单和剩余容量。
3. 点击“导出名单”“导出统计”，用 Excel 打开 CSV，核对中文、时间和四项统计。超过 20 条记录时，导出包含全部分页的记录。
4. 以 `he_qm` 登录，重复查询和导出，确认可以查看不同组织者的活动；以 `zhao_ming` 登录，只能看到其本人活动。

## 状态变化

1. 创建一个未来场次，容量为 1，报名截止时间设在未来，提交并由管理员审核发布。
2. `lin_zy` 报名，`chen_an` 加入候补。组织者刷新统计，应为报名 1、到场 0、缺席 0、剩余 0。
3. `lin_zy` 取消报名，`chen_an` 自动递补。刷新名单，人员状态发生变化，统计仍为 1、0、0、0。
4. 从所选场次进入“签到名单”，为 `chen_an` 签到，再返回统计。应为 1、1、0、0；名单显示首次签到时间。
5. 取消该场次，刷新名单和统计。两条报名记录为已取消，统计为 0、0、0、1，签到时间仍保留。
6. 另选一个已结束且有缺席记录的场次，核对缺席计入报名人数，且不计入到场人数。

## 日志查询

1. 用组织者打开“操作日志”，选择上述活动、场次、时间范围和操作类型，查询报名、取消、递补、签到等记录。
2. 点击记录，核对操作人、时间、目标和结果。自动递补等操作显示为系统执行；修改成功记录可查看前后内容。
3. 在有报名的场次把容量改为小于报名人数，确认操作被拒绝。查询“修改名额”的失败日志，详情显示失败原因。
4. 用管理员查看同一批日志，再切换其他组织者活动；组织者只能查看本人活动范围。
5. 用参与者登录，导航无名单统计和管理日志入口；直接访问 `/admin/logs`、`/organizer/statistics` 返回权限拒绝。
