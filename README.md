# 校园工作坊报名与候补管理系统

南京大学《软件工程》课程实验项目，对应“活动票务与报名系统”选题。项目面向本校免费线下工作坊，围绕活动发布、场次报名、候补递补和现场签到开展需求分析、软件设计与实现。

目前已完成实验一的需求分析和实验二的软件设计，形成 20 条已确认需求、4 张 UML 图和 9 张 UI 界面。实验三已实现登录权限、活动查询，以及活动与场次创建、审核和首次发布，源码在 [code/](code/)。

## 用户与主要功能

| 用户角色 | 主要操作 |
|---|---|
| 参与者 | 查询活动、报名或加入候补、取消报名或退出候补、查看本人报名结果。 |
| 组织者 | 管理本人负责的活动和场次、设置名额、办理签到、查看和导出名单与统计、查询相关日志。 |
| 管理员 | 审核活动与场次、取消活动或场次、查询全平台日志、查看和导出全平台名单与统计。 |

系统设计划分为六个功能模块：身份与权限、活动与场次、报名与候补、签到与缺席、名单与统计、操作日志。

主要业务流程：

创建活动与场次 → 审核发布 → 查询与报名／候补 → 取消后自动递补 → 现场签到 → 名单与统计

一个活动可以包含多个场次，每个场次拥有独立的名额池和候补队列。候补按加入顺序递补；取消报名与自动递补在同一事务中完成。报名记录包含候补中、报名成功、已取消、已签到、缺席和候补未成功六种状态。

## 实验三实现安排

技术栈采用 Java 21、Spring Boot 3.5.16、Spring Security、Thymeleaf、MySQL 8.4 和 JdbcTemplate，使用 Maven Wrapper 3.9.16 构建，JUnit 与 Checkstyle 验证。源码在 `code/` 中按业务模块组织。启动、初始化和测试见 [code/README.md](code/README.md)。

每轮新增及改写的手写非空行不超过 2000 行，包含测试、页面、SQL 和配置。本助手负责实现、审查与修复，可调用子 Agent 分工，项目负责人确认合并。每轮从最新 `main` 创建任务分支，通过一个 PR 审查后以 Squash and merge 合并。

当前阶段与下一步统一记录在 [PROGRESS.md](PROGRESS.md)，详细任务和验收标准见 [PROJECT.md](PROJECT.md)。
